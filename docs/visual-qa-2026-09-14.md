# Updates and Autopilot visual QA

Scope: production Updates and Autopilot, 1440×900 and 390×900. Actual browser recordings, not screenshot montages. Private screenshots stayed local; API content was pseudonymized before sending recordings through OpenRouter to Google `google/gemini-3.7-flash`.

Evidence: `/tmp/feather-visual-before/` and `/tmp/feather-visual-after/` contain videos, screenshots, telemetry and structured model findings. Before-navigation source window 5.5–8.7 seconds was also reviewed at 4× slow motion. Model timestamps in that slow clip are clip-relative.

## Verified and addressed

- Before, Autopilot placed numerous unconfigured chats and expanded task forms above active work. Active chats now lead; unconfigured inboxes and stopped chats are explicitly revealable. Search includes hidden inboxes. Project setup forms are collapsed by default.
- Before-navigation 6–8s: several empty-state panels and a late subtitle caused a misleading empty flash/layout shift. Header copy is stable and project/active-chat loading states are explicit.
- Updates had two headings and two Refresh buttons. It now has one page heading and one refresh control; research management is compact.
- Desktop/mobile page spacing follows the existing workspace system. Task status and title are aligned; large project instructions are folded into the editable direction disclosure.
- Follow-up review identified noisy zero-iteration counters and low-contrast status labels. Zero counters are hidden and status text uses the primary foreground, with a supplementary colored dot.

## Interpretation and remaining work

The model inferred duplicate React items from identical anonymized project labels. This is not supported: Feather uses Solid and these were distinct unconfigured chats with the same display name, not duplicated IDs. No records were deleted or deduplicated.

The second pass recommends combining active chat telemetry with project tasks and increasing feed density. Those are useful follow-ups, not evidence of broken controls. The existing bounded central column is intentionally retained for consistency/readability. Chat execution status and task review status describe different things and have not been conflated.

Old scheduler notices still appear in chronological Updates. This visual change does not fabricate results, remove history, change scheduling, or stop any agents. A richer progress summary requires actual runtime/task evidence, not decorative counters.

## Verification

Browser coverage includes desktop/mobile navigation, stopping autonomous continuation, creating and retrying tasks, editing project direction across polls, review detail caching/invalidation, unblocking tasks, loading without overlapping polls, revealing empty inboxes, and Updates filtering/refresh. Frontend production build passes. Standalone TypeScript checking still reports pre-existing declaration/application errors outside this layout change.
