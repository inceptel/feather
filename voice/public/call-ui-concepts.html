Voice call UI: five concepts

Mock concepts for the Feather voice page. All of them cover pause/resume, mic mute, voice output,

call status and end call. Text wireframes only; nothing here is built.

Today's page: one round button ("Talk", then "Pause call", then a larger amber "Resume"), a small

round speaker button, a status pill in the header, and a small "End call now" link that shows only while paused.

A pause ends the call after 5 minutes.

Terms used below

  • Pause = mic off + voice off, and the call stays open (5-minute limit).
  • Mute mic = only your mic is off. You still hear the voice and Feather results.
  • Voice off = you don't hear the voice. Your mic stays on (useful in a meeting, or with captions).

1. Minimal: one button

┌──────────────────────────────┐
│ Voice              ● Live    │
│                              │
│   (transcript / task cards)  │
│                              │
│          ╭────────╮          │
│          │ Pause  │          │
│          │  call  │          │
│          ╰────────╯          │
│         End call             │
└──────────────────────────────┘
Paused:  ● Paused · ends in 4:32
          ╭────────╮
          │ Resume │   (amber)
          ╰────────╯
         End call
  • Flow: Talk → Pause call ⇄ Resume. End call is always a small text link under the button.
    • No mute and no speaker control. Pause covers both.
  • Rationale: the fewest decisions while driving or walking. This is close to what is live today.
  • Pros: you can't get into a confused state (for example mic off while you think you're live). Easy to use without looking.
  • Cons: you can't listen without being heard. Pausing also stops Feather results from being spoken until you resume.
  • Wording:
    • Use "Pause call" and "Resume", not "Pause" alone.
    • Show the countdown only when under 1 minute remains, to cut the noise.
    • Use "End call", not "End call now".

2. Prominent pause/resume (pause is the hero)

┌──────────────────────────────┐
│ Voice   ● Live · 03:12       │
│  (transcript)                │
│ ┌──────────────────────────┐ │
│ │      ❚❚  Pause call      │ │  ← full-width bar, 72 px
│ └──────────────────────────┘ │
│  🎤 Mute mic     🔊 Voice on   │  ← small secondary toggles
│           End call           │
└──────────────────────────────┘
Paused: the whole footer turns amber
│ ┌──────────────────────────┐ │
│ │     ▶  Resume call       │ │
│ └──────────────────────────┘ │
│  Paused · mic and voice off  │
│  Call ends in 4:32           │
  • Flow:
    • The wide bar toggles pause.
    • The secondary toggles stay usable while paused and apply after you resume.
    • End call asks "End call?" only when Feather tasks are still running.
  • Rationale: pause is the action you use most, so it gets the biggest target. Mute and voice are still there for the less common cases.
  • Pros: you can't miss the paused state, because the whole footer changes color. Fast to hit with a thumb.
  • Cons: three ways to go "quiet" can confuse: Pause, Mute mic and Voice off.
  • Wording:
    • Label the toggles by their state: "Mic on" / "Mic muted" and "Voice on" / "Voice off".
    • Never use "Unmute" as a label. It reads as the current state.

3. Separate mic and speaker controls (phone-call style)

┌──────────────────────────────┐
│ Voice  ● Live  Feather: 2 busy│
│  (transcript)                │
│                              │
│   ╭────╮   ╭────╮   ╭────╮    │
│   │ 🎤 │   │ ❚❚ │   │ 🔊 │    │
│   ╰────╯   ╰────╯   ╰────╯    │
│    Mic     Pause     Voice   │
│                              │
│          ╭──────╮            │
│          │  ✕   │  (red)     │
│          ╰──────╯            │
│          End call            │
└──────────────────────────────┘
  • Flow:
    • Each toggle shows a slash and a red fill when off.
    • Pause dims Mic and Voice, because they are overridden.
    • Resume restores what they were set to before the pause.
  • Rationale: it matches the phone-call screen everyone already knows (FaceTime or a regular phone call).
  • Pros: you know where everything is. It allows listen-only (Mic muted) and silent (Voice off) modes.
  • Cons:
    • It has the most controls.
    • Pause plus Mic is two controls for nearly the same thing.
    • The red End call button is easy to hit by mistake.
  • Wording:
    • Put a text label under every icon. Icons alone are not enough.
    • Use "Voice" rather than "Speaker", since it controls the assistant's audio and not your phone speaker.

4. Accessibility first: large targets, clear labels

┌──────────────────────────────┐
│  CALL IS LIVE                │  ← big text status, also announced
│  Feather is working on 1 task│
│                              │
│ ┌──────────────────────────┐ │
│ │  Pause call              │ │  ≥ 64 px tall, full width
│ │  Mic and voice turn off  │ │  ← second line explains it
│ └──────────────────────────┘ │
│ ┌────────────┐┌────────────┐ │
│ │ Mic: ON    ││ Voice: ON  │ │  ≥ 56 px, words, not icons
│ └────────────┘└────────────┘ │
│ ┌──────────────────────────┐ │
│ │  End call                │ │  outlined, at the bottom, far from Pause
│ └──────────────────────────┘ │
└──────────────────────────────┘
  • Flow:
    • Every change is spoken by a screen reader through an aria-live status ("Call paused. Mic and voice off.").
    • It also plays a short tone when you pause or resume.
    • Keyboard shortcuts: Space for Pause/Resume, M for Mic, V for Voice, Esc then Enter for End call.
    • End call needs a second tap, or a hold for 1 s.
  • Rationale: it can be used with low vision, shaky hands, a screen reader, or in sunlight in a car.
  • Pros:
    • States are shown in words, not color alone.
    • The targets are hard to miss.
    • The destructive action is kept apart from the others.
  • Cons: it takes up more screen, so the transcript area shrinks. It may look heavy for everyday use.
  • Wording:
    • Use "Mic: ON" / "Mic: OFF". The state goes in the label, and there are no verbs to puzzle over.
    • The status line should be a full sentence ("Call is paused. It ends in 4 minutes.").

5. Compact desktop style

┌────────────────────────────────────────────────────────────┐
│ Voice  ● Live 03:12  ·  gpt-realtime · Feather 2/4 busy      │
│ (transcript and task cards, wide)                          │
│                                                            │
├────────────────────────────────────────────────────────────┤
│ [❚❚ Pause] [🎤 Mic ▾] [🔊 Voice ▾]  Type here…  [Send]  [End] │
└────────────────────────────────────────────────────────────┘
  • Flow:
    • One toolbar row.
    • The Mic and Voice dropdowns choose the device (which mic, which output) and also mute.
    • Hover shows the keyboard shortcut.
    • Paused tints the toolbar amber and shows "Paused 4:32" in the status.
    • It can collapse to a floating mini-bar when the tab is in the background (Picture-in-Picture style).
  • Rationale: made for Allan at a desk, typing and talking side by side. It keeps the transcript large.
  • Pros: dense and fast with the keyboard. It allows choosing devices (a headset versus the laptop mic).
  • Cons: the targets are too small for a phone or a car. It needs a separate mobile layout.
  • Wording:
    • Use short verbs on the buttons ("Pause", "End") and put the details in tooltips.
    • In the status bar, say "Paused" rather than an icon only.

Recommendation

  • On the phone: use concept 1 (minimal), which is what's live today. Add one optional "Listen only" mode later, only if you miss muting the mic.
  • On the desktop: use concept 5.
  • From concept 4, take these whatever layout wins:
    • aria-live status announcements,
    • text labels that show the state,
    • End call kept apart from Pause.

Wording rules for all of them

  • Label a toggle by its current state ("Mic: OFF"), or by a clear action ("Pause call" / "Resume"). Never mix the two.
  • Say "Voice" for the assistant's audio and "Mic" for yours. Avoid "Speaker" and "Mute" on their own.
  • Use "End call", not "Hang up" or "Stop". On this page "Stop" already means "stop the Feather task".
  • Say in words what Pause turns off: "mic and voice off".
